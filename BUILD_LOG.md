# Build Log — FDE Cohort 5 Capstone

Running log of problems faced, strategies tried and rejected, and decisions made — updated as we build, not at the end. This feeds the "AI evidence: failure modes" deliverable and the demo's tradeoffs section.

Format: date — problem/decision — what we tried — what we chose and why.

---

## 2026-08-22 — Session 1 (problem understanding)

**Problem: assignment photos wouldn't attach to the AI chat.**
The instruction-packet photos were iPhone HEIC files renamed to `.png`, which the chat couldn't process. Tried attaching directly (failed 3x) → located originals in Downloads and converted with macOS `sips` to JPEG. Lesson: share screenshots as real PNG/JPEG going forward.

**Decision: Track 2 (Prior Authorization Intake Workflow Agent) over Track 1 (Claims Exception Triage).**
Why: missing-info detection has deterministic ground truth (required-fields checklist) → credible evals; human approval gate is built into the ask → enterprise-controls story is natural; prior-auth burden is UHC's most visible pain point → stronger sponsor narrative. Risk accepted: larger surface than Track 1; mitigated by scoping to a 4-step pipeline (extract → completeness check → draft follow-ups → route) with one approval gate.

**Decision: adopt loop-engineering Loops 1–2 only** (agent loop + rubric-based verification loop with retry), per the LangChain "Art of Loop Engineering" article. Loops 3–4 (event-driven triggers, hill-climbing on traces) deferred to the "next iteration path" section — out of scope for a 6-day demoable build.

**Decision: no Playwright/browser automation.** Pipeline logic gets pytest; the approval-gate UI is demoed live. Revisit only if the UI grows.

**Decision: synthetic data will be generated by our own script** (~20–30 PA intake packets: complete / missing-field / ambiguous / edge cases). No external dataset, zero PHI risk, and the generator itself is part of the artifact.

**Open (for next session):** stack choice — plain Python pipeline vs LangGraph `interrupt()` for the human gate; eval metrics definition; work-back schedule Aug 23–28.

## 2026-08-22 — Session 2 (full build)

**Decision: plain Python over LangGraph — resolved.** The human gate is one
approval step, not a resumable graph; Streamlit's rerun model + a decisions
file gives the same interrupt semantics with zero new dependencies. LangGraph
stays in future-work if the workflow grows multi-step approvals.

**Decision: offline-first design.** The judges' own rule — "a prototype that
runs on sample inputs beats an ambitious build no one can execute" — means the
repo must run with **no API key**. Every LLM step (clinical-notes judgment,
letter drafting) has a deterministic fallback (keyword heuristic, templates),
selected automatically when `ANTHROPIC_API_KEY` is absent or any API call
fails (including safety-classifier refusals). LLM mode is an upgrade, not a
requirement. This also became the enterprise "graceful degradation" story.

**Decision: deterministic wherever a rule can decide.** Field presence, NPI
Luhn checksum (real 80840-prefix algorithm), ICD-10/CPT format, eligibility
lookup, and all routing are plain Python. LLM only where language
understanding is required. Routing must be explainable line-by-line.

**Strategy rejected: LLM-as-judge for the letter rubric.** First plan was to
have a second LLM call grade drafted letters. Realized the rubric is fully
checkable in code (findings covered? nothing invented? case ID present?) —
cheaper, deterministic, and it works offline. LLM-judge adds nothing here.
Loop 2 kept: draft → code-rubric → one retry with feedback → template fallback.

**Problem: golden labels could leak into the pipeline.** Generator emits
labels by construction; if the pipeline read them it would "score" 100%
dishonestly. Fix: labels live in `data/golden_labels.json`, read only by
`evals/run_evals.py`; packets carry no scenario metadata.

**Problem: two Luhn implementations (generator + validator) could diverge.**
Accepted the duplication (cross-importing data/ from src/ is uglier) and added
`test_generator_npis_pass_validation` to catch divergence.

**Result: offline eval = 100% precision/recall, 26/26 routing, 15/15 letter
rubric.** Framed honestly in README/DESIGN as a consistency check of the
deterministic path against by-construction labels — not proof of intelligence.
LLM-mode variance is the interesting measurement; failure modes listed in
DESIGN §5.

**Verified:** 17/17 pytest, evals green, CLI smoke run on all 26 packets,
Streamlit app boots headless (HTTP 200).
